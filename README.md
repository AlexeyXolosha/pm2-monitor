# PM2 Monitor

Небольшой Go-сервис для мониторинга процессов, запущенных через [PM2](https://pm2.keymetrics.io/).

Раз в заданный интервал он вызывает `pm2 jlist`, смотрит на RAM, CPU, статус и
количество рестартов каждого процесса, формирует отчёт и отправляет его в Telegram.
Если процесс упал или превысил лимит памяти — присылает отдельный алерт.

Запускается сам под управлением PM2, поэтому cron не нужен.

## Как это устроено

```
pm2-monitor/
├── cmd/monitor/main.go        # точка входа: склеивает всё вместе
├── internal/
│   ├── config/config.go       # чтение настроек из .env
│   ├── pm2/client.go          # вызов `pm2 jlist` и парсинг JSON
│   ├── telegram/client.go     # отправка сообщений в Telegram
│   └── monitor/monitor.go     # главный цикл: опрос → отчёт → алерты
├── .env                       # секреты (НЕ коммитится)
├── .env.example               # шаблон настроек (коммитится)
└── go.mod
```

Поток данных на каждом «тике» таймера:

```
ticker → monitor.check() → pm2.GetProcesses() → строим отчёт → telegram.SendMessage()
```

## Настройка

1. Установи зависимости:
   ```bash
   go mod tidy
   ```

2. Создай `.env` из шаблона и заполни своими значениями:
   ```bash
   cp .env.example .env
   ```

   | Переменная            | Описание                                  | Пример  |
   |-----------------------|-------------------------------------------|---------|
   | `TELEGRAM_BOT_TOKEN`  | Токен бота из [@BotFather](https://t.me/BotFather) | `123:ABC...` |
   | `TELEGRAM_CHAT_ID`    | Куда слать сообщения (см. [@userinfobot](https://t.me/userinfobot)) | `123456789` |
   | `CHECK_INTERVAL`      | Интервал опроса (`30s`, `5m`, `1h`)       | `1h`    |
   | `MEMORY_LIMIT_MB`     | Порог RAM для алерта, в МБ                 | `1024`  |

## Запуск

Локально для проверки:

```bash
go run ./cmd/monitor
```

Собрать бинарник:

```bash
go build -o bin/monitor ./cmd/monitor
```

## Запуск под PM2 (на сервере)

```bash
go build -o bin/monitor ./cmd/monitor
pm2 start ./bin/monitor --name pm2-monitor
pm2 save
```

## Идеи для развития

- Детект «резкого» роста RAM (сравнивать с предыдущим замером, а не только с лимитом).
- Алерт при росте числа рестартов между проверками.
- Не слать полный отчёт каждый раз, а только при изменениях/проблемах.
- Ретраи при временной ошибке Telegram API.
